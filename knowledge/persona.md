### AI 溶栓助手

- 类型与标签：UX、医疗 AI、急诊流程、可解释 AI、校企合作项目。
- 项目背景：急性缺血性脑卒中的溶栓治疗存在严格时间窗，医生需要在很短时间内综合症状、检查结果、既往病史、影像与凝血指标等复杂信息，并与家属沟通风险。
- 项目目标：设计一个嵌入真实卒中急救流程的 AI 溶栓辅助系统，通过结构化信息采集、关键因素整合、风险评估和可解释结果展示，帮助医生更快、更准确地完成溶栓决策。
- 我的工作：负责项目流程与用户研究，输出完整交互方案和视觉方案；整理院前到院内流程，分析医生与家属痛点，构建信息架构、流程优化、组件系统与关键页面。
- 核心洞察：医生痛点在于时间延误与信息复杂并存；家属痛点在于缺乏溶栓认知，却要在高压情境下快速签署知情同意。
- 设计方案：将院前信息录入、入院检查、条件评估、治疗执行串联成连续流程；用状态标签、结构化表单、大尺寸控件、多模态录入和 AI 诊断结果解释降低急诊场景中的操作与理解负担。
- 设计系统：使用蓝色医疗主色、状态色、分层字体与图标规范，强调“清晰高效、负责可靠、流程真实”。
- 可回答角度：医疗 UX、AI 决策支持、可解释 AI、急诊流程优化、复杂信息架构、医生与家属双侧体验。

### AI 如何帮助 ADHD

- 类型与标签：UX、产品、HCI、前端开发、硬件编程、LLM、独立开发。
- 项目背景：ADHD 青年常见困难不是“不知道任务是什么”，而是难以启动任务。传统任务管理工具往往默认用户已经具备启动能力，过度记录和规划反而可能增加压力与挫败感。
- 项目目标：为 18-25 岁 ADHD 青年设计一个帮助任务启动的 LLM 游戏化系统，用 AI 拆解任务、硬件提供环境提示、花园反馈提供非评判式鼓励。
- 我的工作：负责前端开发、硬件编程和交互设计，完成从研究框架、原型设计、LLM API 调用、ESP32 / Arduino 硬件交互到用户研究计划的完整闭环。
- 理论基础：参考 Thomas E. Brown 的 ADHD 执行功能模型，聚焦 activation、组织、时间管理与任务启动障碍。
- 设计方案：用户用自然语言输入当前状态和目标，LLM 将模糊目标拆成最小可执行步骤，并解释每一步为什么这样做；硬件屏幕、按钮和 LED 同步任务进度；App 通过花园系统呈现持续反馈。
- 交互原则：轻量开始、非评判反馈、用户可跳过、AI 可解释、硬件降低屏幕依赖。
- 用户研究计划：采用混合方法、A/B 对照与半结构访谈，观察系统是否能降低启动门槛、提高控制感并减少心理负担。
- 可回答角度：HCI 研究、ADHD 辅助技术、AI 产品、硬件交互、LLM prompt 控制、独立全栈原型。

### Search Focus

- 类型与标签：插件、浏览器插件、注意力保护、信息流体验。
- 项目简介：Search Focus 是网页版小红书首页信息流模糊插件，适配 Chrome、Firefox、Edge、Atlas 等浏览器。
- 项目背景：很多用户打开小红书原本是为了搜索某个问题，但首页推荐信息流会先占据注意力，导致搜索意图被打断。
- 项目目标：减少推荐流对搜索任务的干扰，让用户在打开网页时更容易保持原本的搜索意图。
- 设计方案：首页默认模糊并变暗推荐信息流，突出搜索入口；搜索框区域保持清晰可用；用户也可以通过开关一键切换专注模式。
- 隐私原则：不发送网络请求，不收集数据，只在本地改变页面视觉呈现。
- GitHub：<https://github.com/xjqdzkkhts-cmd/focus-search-xiaohongshu>
- 可回答角度：浏览器插件、注意力管理、微交互、隐私友好工具、从个人痛点出发的轻量产品。

### MarkCode

- 类型与标签：插件、Figma 插件、Figma to Code、AI 工作流、Vibe Coding。
- 项目简介：MarkCode 是面向快速创意时期的 Figma to Code 插件，选择 Figma 图层后，可以生成可复制给 Codex 的 Markdown 规范，把复杂设计元素转化成 AI 更容易理解的结构化说明。
- 项目背景：自然语言很难精准描述复杂局部 UI，例如异形标签、卡片、渐变、模糊、局部装饰与复杂层级。Figma MCP 更适合结构规范、Auto Layout 完善的整体页面搭建，而 MarkCode 更适合创意早期的复杂局部元素还原。
- 核心工作流 1：代码交付辅助。设计师确认 Figma 高保真稿后，MarkCode / AI 读取图层结构与样式，输出 HTML / CSS / JS 等前端代码，适合 B 端后台、数据看板等页面交付。
- 核心工作流 2：设计生成辅助。用户输入 PRD、需求描述或规范文档，AI 拆解页面结构、生成模块清单和设计 token，再产出可编辑设计稿或 HTML 预览，设计师继续在 Figma 中微调。
- 关键优势：比单纯用自然语言描述更准确，比完整 MCP 流程更轻量，适合选中局部元素后快速生成结构化说明并交给 AI 生成代码。
- 设计重点：Figma 选区解析、结构化 Markdown 输出、辅助 Codex / Cursor 理解设计规则、降低 Vibe Coding 的表达成本。
- GitHub：<https://github.com/xjqdzkkhts-cmd/MarkCode>
- 可回答角度：AI 工作流、Figma 插件、设计到代码、Vibe Coding、设计师如何独立构建工具。

### Relight

- 类型与标签：产品、可持续设计、能源基础设施、服务系统。
- 项目简介：Relight 是一个社区能源站概念，围绕“Battery’s Second Life”重新利用退役电动车电池，为公园照明和城市基础设施提供可持续能源。
- 项目背景：到 2035 年，大量 EV 电池将进入退役阶段，但许多电池仍保留约 80% 原始容量。退役电池若处理不当会带来健康、水污染、土壤污染、土地资源浪费和高昂清洁成本。
- 项目目标：探索如何在 Queen Elizabeth Olympic Park 场景中，将二次生命 EV 电池转化为可规模化、包容性的公共基础设施能源方案。
- 设计方案：白天由顶部太阳能板收集能源并存储到二次生命电池中，夜间为街灯和公共设施供电；透明前面板让公众看到被重新利用的电池，提升理解与信任。
- 功能场景：日间吸收太阳能、提供应急电源；夜间为街灯供电；作为社区能源节点与可持续教育展示装置。
- 可行性数据：6 平方米太阳能顶棚约产生 2.98 kWh / day；每盏 30W 公园灯 10 小时耗电约 0.30 kWh；一个 Relight 节点约可支持 10 盏公园灯；简单回收期约 12 年。
- 设计重点：可持续产品、公共基础设施、能源可视化、环境教育、二次生命电池再利用。
- 可回答角度：产品设计、可持续设计、服务系统、能源计算、公共空间设计。
